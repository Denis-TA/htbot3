# hrbot3

Телеграм-бот, который следит за новыми вакансиями на hh.ru и присылает подходящие
в личку. Умеет писать сопроводительные письма через ИИ (Groq) по твоему резюме.

Бот персональный: отвечает только одному пользователю — тому, чей ID указан
в переменной `OWNER_ID`. Всем остальным он молчит.

---

## Что умеет

- **Мониторинг hh.ru.** Каждые 5 минут проверяет новые вакансии по твоим фильтрам.
  Одна вакансия приходит только один раз, даже если подходит под несколько фильтров.
- **Гибкие фильтры.** Ключевые слова, город, вилка зарплаты, опыт, тип занятости,
  график, формат работы (офис / удалёнка / гибрид). Фильтров может быть сколько
  угодно, каждый можно поставить на паузу.
- **ИИ-сопроводительные.** Кнопка под вакансией генерирует письмо по твоему резюме
  и добавляет его прямо под карточку. Пишет строго по резюме, без выдуманного опыта.
- **Чёрный список компаний.** Одна кнопка — и вакансии этого работодателя
  больше не приходят.
- **Свой промпт.** Инструкцию для ИИ можно переписать под себя.

---

## Как пользоваться

Напиши боту `/start` — он поздоровается и покажет меню.

| Кнопка | Что делает |
|---|---|
| 📋 Мои фильтры | список фильтров: открыть, изменить, пауза, удалить |
| ➕ Создать фильтр | пошаговое создание нового фильтра |
| ✏️ Редактировать резюме | вставить или заменить резюме (текстом или `.txt`) |
| ⚙️ Промпт ИИ | изменить инструкцию, по которой пишутся письма |

### Ключевые слова

Несколько запросов задаются через запятую — каждый ищется отдельно, результаты
объединяются:

```
product analyst, продуктовый аналитик, аналитик данных
```

Точная фраза — в кавычках: `"product manager"`.
Поиск идёт **по названию вакансии**, не по описанию.

Если не знаешь, что вписать — на шаге ключевых слов есть кнопка
«💡 Предложить ключевые (ИИ)».

### Сопроводительные письма

Два способа:

1. Кнопка **🤖 ИИ-отклик** под присланной вакансией — письмо добавится под карточку.
2. Отправить боту **ссылку на вакансию** hh.ru (или просто её номер) — он ответит
   готовым письмом.

Письмо приходит в блоке кода — тапни, чтобы скопировать целиком.
Сначала добавь резюме, иначе письму не на что опираться.

### Скрытые компании

Кнопка **🚫 Скрыть все вакансии компании** под вакансией. Названия сравниваются
без учёта регистра, кавычек, лишних пробелов и `ё`/`е`. Правовые формы
(`ООО`, `АО`, `ИП`) **не** отбрасываются — «ООО Ромашка» и «АО Ромашка»
считаются разными компаниями.

Посмотреть и снять блокировки — команда `/blocked`.

### Команды

| Команда | Действие |
|---|---|
| `/start`, `/help` | приветствие и меню |
| `/filters` | список фильтров |
| `/newfilter` | создать фильтр |
| `/blocked` | скрытые компании |
| `/cancel` | прервать текущий диалог |

## Переменные окружения

| Переменная | Обязательна | Где взять |
|---|---|---|
| `BOT_TOKEN` | да | [@BotFather](https://t.me/BotFather) в Telegram: `/newbot`, дальше по шагам |
| `OWNER_ID` | да | [@userinfobot](https://t.me/userinfobot): напиши ему что угодно, он ответит твоим ID |
| `GROQ_API_KEY_1` | для писем | [console.groq.com/keys](https://console.groq.com/keys) — регистрация бесплатная |
| `GROQ_API_KEY_2` … `_5` | нет | там же, дополнительные ключи (см. ниже) |
| `DATABASE_URL` | нет | подставляется автоматически, если подключить PostgreSQL на хостинге |
| `TELEGRAM_PROXY` | нет | адрес своего прокси, если Telegram недоступен напрямую |
| `LOG_FILE` | нет | имя файла логов, по умолчанию `bot.log` |

Без `GROQ_API_KEY_1` бот работает, но кнопка ИИ-отклика будет возвращать ошибку.

**Про запасные ключи Groq.** У бесплатного тарифа есть лимит запросов. При ответе
`429` бот сам переключается на следующий ключ и присылает уведомление. Ключи
берутся из разных аккаунтов Groq. Неиспользуемые слоты заполняются значением
`123` — оно считается заглушкой и игнорируется.

Раньше первый ключ назывался просто `GROQ_API_KEY`. Это имя всё ещё работает —
если задано и оно, и `GROQ_API_KEY_1`, побеждает `GROQ_API_KEY_1`.

**Про базу.** Если `DATABASE_URL` задана — бот пишет в PostgreSQL, иначе в локальный
файл `hrbot.db` (SQLite). Схема создаётся сама при первом запуске.

## Запуск на своём компьютере

Нужен Python 3.11+.

```bash
git clone https://github.com/Denis-TA/htbot3.git
cd htbot3
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

Скопируй `.env.example` в `.env` и впиши свои значения:

```bash
copy .env.example .env
```

Запуск:

```bash
.venv\Scripts\python bot.py
```

Или двойным кликом по `start.bat`. Останавливается через `Ctrl+C` или `stop.bat`.

Пока бот запущен на компьютере — он проверяет вакансии. Выключил компьютер —
проверки прекратились. Для круглосуточной работы нужен хостинг.

## Запуск на Railway

[Railway](https://railway.app) — хостинг, который умеет разворачивать проект прямо
из GitHub-репозитория. Бесплатного тарифа нет, самый дешёвый — Hobby.

1. **Залей проект на GitHub**, если его там ещё нет.

2. На [railway.app](https://railway.app) зарегистрируйся через GitHub.

3. **New Project → Deploy from GitHub repo** → выбери свой репозиторий.
   Railway сам увидит Python и `requirements.txt` и соберёт проект.

4. **Добавь переменные.** Вкладка **Variables** у сервиса → **New Variable**.
   Заведи как минимум `BOT_TOKEN`, `OWNER_ID` и `GROQ_API_KEY` — значения те же,
   что в локальном `.env`. Есть кнопка **Raw Editor**: можно вставить сразу
   несколько строк в формате `КЛЮЧ=значение`.

   Файл `.env` на Railway **не попадает** — он в `.gitignore`, и это правильно.
   Переменные задаются только через интерфейс Railway.

5. **Проверь процесс.** В `Procfile` описаны два процесса:

   ```
   worker: python bot.py
   web: python -m http.server $PORT
   ```

   Бот — это `worker`. Убедись, что запущен именно он.

6. **База данных (желательно).** Без неё файл `hrbot.db` будет стираться при каждом
   передеплое вместе с фильтрами и резюме. **New → Database → Add PostgreSQL**,
   Railway сам подставит `DATABASE_URL`, и бот переключится на неё автоматически.

7. **Логи** — вкладка **Deployments** → **View Logs**. При успешном старте там будет
   `Bot polling started.`

Если `OWNER_ID` не задать, бот не запустится и напишет об этом в логах — это
намеренно, иначе он молча игнорировал бы все сообщения.

> **Важно: не запускай два экземпляра сразу.** Если бот работает на Railway и
> одновременно на компьютере, Telegram будет отдавать ошибку `409 Conflict` —
> получать сообщения может только один. К тому же базы у них разные, так что
> вакансии придут дважды.

## Как это устроено

| Файл | Назначение |
|---|---|
| `bot.py` | команды, кнопки, диалоги, планировщик проверок |
| `hh_api.py` | поиск вакансий через RSS hh.ru |
| `ai.py` | Groq: письма и подсказка ключевых слов, парсинг страницы вакансии |
| `db.py` | SQLite / PostgreSQL: фильтры, резюме, блок-лист, журнал отправленного |
| `config.py` | чтение переменных окружения |
| `utils/formatting.py` | оформление карточек вакансий |

Вакансии берутся из **RSS-выдачи** hh.ru, а не из официального API — поэтому
OAuth и регистрация приложения не нужны.

Защита от дублей двухуровневая: `seen_vacancies` помнит просмотренное по каждому
фильтру, а `sent_vacancies` — всё, что вообще отправлялось. Второй уровень нужен
потому, что одна вакансия может подойти сразу под несколько фильтров.
